# 双倒立摆 —— 浏览器中的控制

本仿真将小车上的双倒立摆从自然下垂的静止状态起摆到竖直的 **up-up 位姿**，
并保持在该位姿。控制器由三部分组成：

* 围绕上平衡点的 **LQR 状态反馈**，其增益是代数 Riccati 方程的精确解
  （矩阵符号函数法）；
* 通过 **轨迹优化实现起摆**（在完整非线性模型上运行 iLQR），由 **时变 LQR**
  跟踪；
* 通过能量抽取实现的 **静息过程**，在每次尝试前把系统带到规划轨迹的起始状态。

起摆与平衡之间的交接点不是经验阈值，而是 Riccati 矩阵的一个子水平集。

全部计算 —— 包括 Riccati 求解器与轨迹优化 —— 都以 JavaScript 在浏览器中实时
运行，不依赖任何库。

---

## 1. 物理模型

### 1.1 坐标与状态空间

状态向量有六个分量：

```
x = [x, ẋ, θ₁, θ̇₁, θ₂, θ̇₂]ᵀ
```

| 量 | 含义 | 单位 |
|----|------|------|
| `x`   | 小车位置 | m |
| `ẋ`   | 小车速度 | m/s |
| `θ₁`  | 第一连杆的角度（0 = 竖直向上） | rad |
| `θ̇₁`  | 第一连杆的角速度 | rad/s |
| `θ₂`  | 第二连杆的角度（0 = 竖直向上） | rad |
| `θ̇₂`  | 第二连杆的角速度 | rad/s |
| `θ̈₁`  | 第一连杆的角加速度 | rad/s² |
| `θ̈₂`  | 第二连杆的角加速度 | rad/s² |

**控制输入：** `u` —— 作用于小车的水平力（N）。

### 1.2 参数（默认值）

| 符号 | 数值 | 含义 |
|------|------|------|
| `M`    | 1.5 kg | 小车质量 |
| `m₁`   | 0.50 kg | 第一连杆质量 |
| `m₂`   | 0.50 kg | 第二连杆质量 |
| `L₁`   | 0.40 m  | 第一连杆全长（`L₁ = 2·l₁`） |
| `L₂`   | 0.40 m  | 第二连杆全长（`L₂ = 2·l₂`） |
| `l₁`   | 0.20 m | 第一连杆的质心距离 |
| `l₂`   | 0.20 m | 第二连杆的质心距离 |
| `I₁`   | `¹⁄₁₂·m₁·(0.02 + 4·l₁²)` kg·m² | 第一连杆的转动惯量 |
| `I₂`   | `¹⁄₁₂·m₂·(0.02 + 4·l₂²)` kg·m² | 第二连杆的转动惯量 |
| `g`    | 9.81 m/s² | 重力加速度 |
| `c`    | 0.00 Nms/rad | 关节阻尼 |

对默认值（`m₁ = m₂ = 0.50 kg`，`l₁ = l₂ = 0.20 m`）可得
`I₁ = I₂ ≈ 0.0075 kg·m²`。

*注：参数变化时转动惯量会自动重新计算。滑块直接控制的是 `l₁` 与 `l₂`，
全长由 `L = 2·l` 得出。*

### 1.3 运动方程（拉格朗日方法）

动力学由欧拉-拉格朗日方程给出：

```
d/dt (∂L/∂q̇) − ∂L/∂q = Q
```

其中拉格朗日函数 `L = T − V`（动能减势能），广义坐标为 `q = [x, θ₁, θ₂]ᵀ`。

#### 惯性矩阵 M(q)

```
M₁₁ = M + m₁ + m₂
M₁₂ = (m₁·l₁ + m₂·L₁)·cos(θ₁)
M₁₃ = m₂·l₂·cos(θ₂)
M₂₂ = I₁ + m₁·l₁² + m₂·L₁²
M₂₃ = m₂·L₁·l₂·cos(θ₁−θ₂)
M₃₃ = I₂ + m₂·l₂²
```

对称性：`M₂₁ = M₁₂, M₃₁ = M₁₃, M₃₂ = M₂₃`。

#### 科里奥利矩阵 C(q, q̇)

```
C = [[0, −(m₁·l₁+m₂·L₁)·θ̇₁·sin(θ₁), −m₂·l₂·θ̇₂·sin(θ₂)],
     [0, 0, m₂·L₁·l₂·θ̇₂·sin(θ₁−θ₂)],
     [0, −m₂·L₁·l₂·θ̇₁·sin(θ₁−θ₂), 0]]
```

#### 重力向量 G(q)

```
G(q) = [0, −(m₁·l₁+m₂·L₁)·g·sin(θ₁), −m₂·g·l₂·sin(θ₂)]ᵀ
```

#### 运动方程（隐式形式）

```
M(q)·q̈ + C(q,q̇)·q̇ + G(q) = H(u)
```

其中 `H = [u, 0, 0]ᵀ`。对 q̈ 求解可得：

```
q̈ = M⁻¹(q)·(H(u) − C(q,q̇)·q̇ − G(q))
```

积分采用 **经典四阶龙格-库塔法（RK4）**，固定步长
`dt = 6.25·10⁻⁵ s`（16 kHz）。

#### 能量

势能（相对于竖直静止位姿）。连杆 1 在其顶端承载着连杆 2 的质量，
因此 `m₂·L₁` 也计入其中：

```
Epot = (m₁·l₁ + m₂·L₁)·g·(cos(θ₁)−1) + m₂·l₂·g·(cos(θ₂)−1)
```

连杆的动能 —— 含耦合项 `M₂₃`：

```
Ekin = ½·(M₂₂·θ̇₁² + 2·M₂₃·θ̇₁·θ̇₂ + M₃₃·θ̇₂²)
```

## 2. 部分反馈线性化（PFL）

PFL 把期望的小车加速度 `v` 与摆的动力学解耦。不直接选择力 `u`，
而是给定一个虚拟的小车加速度 `v`，再计算实现它所需的力 `u`。

### 2.1 推导

由 `M(q)·q̈ + C·q̇ + G = H(u)` 的第一行可得：

```
M₁₁·ẍ + M₁₂·θ̈₁ + M₁₃·θ̈₂ + C₁ + G₁ = u
```

连杆加速度 `θ̈₁, θ̈₂` 对 `v = ẍ` 呈仿射关系：

```
θ̈₁ = θ̈₁ᵖ + θ̈₁ᵛ·v
θ̈₂ = θ̈₂ᵖ + θ̈₂ᵛ·v
```

其中 `θ̈ᵖ` 是小车不动时的连杆加速度（仅含科氏项、重力与阻尼），
`θ̈ᵛ` 是单位 `v` 所产生的加速度：

```
θ̈₁ᵖ = (M₃₃·(−C₂−G₂−c·θ̇₁) − M₂₃·(−C₃−G₃−c·θ̇₂)) / (M₂₂·M₃₃ − M₂₃²)
θ̈₂ᵖ = (−M₃₂·(−C₂−G₂−c·θ̇₁) + M₂₂·(−C₃−G₃−c·θ̇₂)) / (M₂₂·M₃₃ − M₂₃²)
θ̈₁ᵛ = (−M₃₃·M₂₁ + M₂₃·M₃₁) / (M₂₂·M₃₃ − M₂₃²)
θ̈₂ᵛ = (M₃₂·M₂₁ − M₂₂·M₃₁) / (M₂₂·M₃₃ − M₂₃²)
```

这里 `C₁, C₂, C₃` 是 `C(q,q̇)·q̇` 的各分量，因此对关节速度是 **二次** 的：

```
C₁ = −(m₁·l₁+m₂·L₁)·sin(θ₁)·θ̇₁²  −  m₂·l₂·sin(θ₂)·θ̇₂²
C₂ =  m₂·L₁·l₂·sin(θ₁−θ₂)·θ̇₂²
C₃ = −m₂·L₁·l₂·sin(θ₁−θ₂)·θ̇₁²
```

### 2.2 PFL 控制律

```
u = α·v + φ

α = M₁₁ + M₁₂·θ̈₁ᵛ + M₁₃·θ̈₂ᵛ
φ = M₁₂·θ̈₁ᵖ + M₁₃·θ̈₂ᵖ + C₁ + G₁
```

于是任何期望的 `v` 都能被精确地转换为力 `u`。

### 2.3 能量平衡

以 `v` 为输入时，连杆对的能量

```
E   = ½·θ̇ᵀ·M_p·θ̇ + a₁·g·cos(θ₁) + a₂·g·cos(θ₂)
a₁  = m₁·l₁ + m₂·L₁,   a₂ = m₂·l₂
M_p = [[M₂₂, M₂₃], [M₂₃, M₃₃]]
```

精确满足

```
Ė = −v·W − c·(θ̇₁² + θ̇₂²),   W = a₁·cos(θ₁)·θ̇₁ + a₂·cos(θ₂)·θ̇₂
```

（科氏项与 `½·θ̇ᵀ·Ṁ_p·θ̇` 相互抵消）。`W` 是小车注入或抽取能量的唯一通道 ——
静息过程（第 6 节）与能量泵送的兜底方案都建立在这个恒等式上。

## 3. 状态机

控制器运行在三个状态中：

| `recoveryState` | 模式 | 说明 |
|------------------|------|------|
| 0 | `LQR Balance` | 围绕上平衡点的状态反馈 |
| 1 | `Settling` | 抽取能量直至下垂静止，并使小车回中 |
| 2 | `Swing-up` | 执行优化得到的起摆轨迹 |

### 状态转移

```
Power ON / Reset → 若状态位于捕获区域内则进入 0，否则进入 1
状态 1：达到下垂静止 ∧ 已有可用轨迹 → 2
状态 2：进入捕获区域 → 0
状态 2：轨迹走完仍未捕获 → 1（重新尝试）
状态 0：|θ₁|>0.8 或 |θ₂|>0.8 持续 >20 个周期 → 1
撞到导轨限位（±2.5 m）→ 1
```

捕获区域 **不是** 经验设定的，而是由 LQR 的 Riccati 矩阵导出（见 4.3 节）。

## 4. LQR 状态反馈（RecoveryState = 0）

### 4.1 线性化

在 `θ₁ = θ₂ = 0, q̇ = 0` 处，`M(q)` 为常数矩阵，`C` 消失，`G` 为线性。
记 `N = M₀⁻¹`，则

```
q̈ = N·([u,0,0]ᵀ − ∂G/∂q·q − D·q̇)
```

由此得到状态模型 `ẋ = A·x + B·u`，其中
`x = [x, ẋ, θ₁, θ̇₁, θ₂, θ̇₂]ᵀ`。对默认参数，开环被控对象的特征值为

```
0, 0, ±4.96, ±11.44   (1/s)
```

—— 两个不稳定极点，正如双倒立摆所应有的。

### 4.2 Riccati 方程的求解

增益是真正求解出来的 LQR 解，而非估计值。所求解的方程为

```
AᵀP + P·A − P·B·R⁻¹·Bᵀ·P + Q = 0
```

方法是求哈密顿矩阵的 **矩阵符号函数**

```
H = [[A, −B·R⁻¹·Bᵀ], [−Q, −Aᵀ]]
```

牛顿迭代 `Z ← ½·(c·Z + (c·Z)⁻¹)` 二次收敛到 `sign(H)`；稳定不变子空间由
`I − sign(H)` 的列张成，其形式为 `[u; P·u]`，由最小二乘即可解出 `P`。
随后若干次 Newton/Kleinman 迭代（把 Lyapunov 方程当作 36×36 线性方程组求解）
将 `P` 精修到机器精度。残差约为 `≈10⁻¹⁰`，耗时仅几毫秒 ——
因此每次参数变化都会重新综合一遍。

权重：

```
Q = diag(5.0 ; 0.1 ; 10 ; 50 ; 10 ; 50)
R = 0.5
```

对小车位置取较小权重、对角速度取较大权重，可以最大化在 ±50 N 执行器限幅内
可达到的吸引域 —— 而起摆过程要命中的正是这个吸引域。

对默认参数可得

```
K ≈ [3.16 ; 6.49 ; −303.4 ; −8.91 ; 343.9 ; 41.4]
u  = −K·(x − 设定点向量),   u = clamp(u, −50, 50)
```

闭环极点为 `−24.60`、`−8.10 ± 4.31i`、`−1.70`、`−0.71 ± 0.81i`。

实测吸引域（非线性仿真，±50 N）：

| 偏移方向 | 边界 |
|----------|------|
| `θ₁ = θ₂`  | ±0.59 rad |
| 仅 `θ₁`   | ±0.36 rad |
| 仅 `θ₂`   | ±0.41 rad |
| `θ̇₁ = θ̇₂`  | ±2.1 rad/s |

### 4.3 捕获区域

一旦满足下式，控制权即交给 LQR：

```
eᵀ·P·e < catchLevel   ∧   |θ₁|,|θ₂| < 0.6   ∧   |θ̇₁|,|θ̇₂| < 4.0   ∧   |x−x_soll| < 2.0
```

那几个显式边界只是合理性保护（避免在角度绕圈的另一侧交接，或恰好贴着限位交接）
—— 真正起决定作用的是子水平集。

小车位置被 **有意** 排除在二次型之外：在交接的瞬间，LQR 的设定位置被移到小车
当前所在之处，随后以 1.5 s 的时间常数回到 `x_soll`。这样全部的力预算都可用于
捕获连杆，而不必花在一个马上就会消失的位置误差上。

该阈值是使未限幅的 LQR 力仍满足执行器限制的最大 `eᵀPe` 子水平集：

```
在 eᵀPe ≤ c 上 max |K·e|  =  √(c · K·P⁻¹·Kᵀ)
⟹ catchLevel = U_max² / (K·P⁻¹·Kᵀ)     (默认参数下 ≈ 28.5)
```

蒙特卡洛采样（每种被控对象取约 100 个被接受的状态，各向前仿真 12 s）对大多数
被控对象完全确认了该集合。剩下两个例外：在 `l₂ = 0.5 m` 时 106 个被接受状态中
丢失了 1 个，在 `g = 1 m/s²` 时 135 个中丢失了 4 个 —— 也就是说该边界乐观了
百分之几，因为它来自 *线性化* 模型。

有两重机制吸收了这一点：

* **规划出的** 起摆轨迹并不依赖这个边界。在被采纳之前，它会被完整仿真一遍 ——
  起摆 *以及* 随后的平衡 —— 只有当 LQR 确实把摆稳稳地停在竖直位姿时才被接受
  （见 5.3 节）。
* 若该判据在 **扰动** 之后确实误判，发散监测会在 20 个计算周期内发现，
  控制器随即静息并重新起摆。

## 5. 通过轨迹优化实现起摆（RecoveryState = 2）

### 5.1 为什么不用纯能量泵送

能量泵送（`v ∝ (E−E_d)·W`）能可靠地把 **总能量** 驱动到上平衡点对应的数值，
却完全无法决定这些能量 **如何** 在两根连杆之间分配。集合 `E = E_d` 是五维的，
而其中的捕获区域小到几乎可以忽略。在默认被控对象上的实测：120 s 的能量泵送中，
两个角度同时小于 0.5 rad 的时间总共只有 **0.06 s**，`eᵀPe` 达到过的最好值是
178，而阈值是 28.5。这样起摆的成功率不到三分之一，成功时的中位耗时约 24 s。

### 5.2 iLQR 轨迹优化

因此这里把起摆当作最优控制问题来求解 —— 在完整非线性模型上运行 **iLQR**，
从下垂静止状态出发：

```
min  ½·w_f·e_Nᵀ·P·e_N  +  Σ_k [ ½·r·w_k² + ½·q_x·x_k²
                               + ρ(k)·(a₁·(1−cosθ₁) + a₂·(1−cosθ₂))
                               + ½·ρ_v(k)·(θ̇₁² + θ̇₂²)  + 导轨壁垒项 ]
```

| 组成 | 取值 / 作用 |
|------|-------------|
| 节点数 `N` | 125（粗）或最多 220（细），随每次重启而变 |
| 时域长度 `T` | `2.5 s · 4.22 / ω_hang`，限制在 1.5–9.0 s，并随重启再乘以 ×1.5 或 ×0.75 |
| 力 | `u = 50·tanh(w)` —— 执行器限幅由构造保证，问题保持无约束 |
| 终端代价 | `eᵀPe` = LQR 的待付代价，恰好就是捕获区域的度量 |
| `ρ(k), ρ_v(k)` | “立起来”的整形项，权重 `∝ (k/N)³` |
| 导轨壁垒项 | 软约束，从 `|x| > 1.2 m` 开始起作用 |

时域长度随下垂双摆的慢特征频率 `ω_hang`（由 `det(K_g − ω²M_p) = 0` 得出）
缩放，使较长或重力较弱的摆按比例获得更多时间。

仅靠终端代价项，优化器的收敛域太小；平滑的“立起来”整形项把它引导过去。
在起始噪声相同的条件下各做五次随机起始的实测：不加整形项时有一次的终端代价
低于 1，加上之后有三次。在加整形项的 14 次起始中，有九次得到了可用解。

**时间分片：** 优化以每动画帧 ≤ 8 ms 的分片运行，此时控制器仍在静息 ——
界面保持流畅。某次重启若在 30 次迭代后仍相差甚远（超过捕获区域的 22 倍），
就直接放弃而不再勉强；而一轮中最后六次尝试则总是跑完。各次重启会轮换四种
“时域长度 × 分辨率”的组合 —— 125 或最多 220 个节点，时域 ×1、×1.5 或 ×0.75。
没有哪一种组合能通吃：粗网格在默认参数下收敛更频繁，很长的连杆只有在细网格上
才能得到可用轨迹，而在小 `g` 时则要靠拉长的时域才能成功。由于每个候选无论如何
都会被完整仿真一遍（见 5.3 节），这里多一些多样性只有好处。

### 5.3 通过闭环仿真进行验收

起摆轨迹是 **开环不稳定** 的。因此仅凭优化的终端代价说明不了什么：同样的力
在不同时间网格上重新积分就会跑飞 —— 实测有一个候选在自己的网格上得分
`eᵀPe = 0.1`，开环重放后却终止于 `eᵀPe > 12 000`。

真正重要的是 **闭环** 行为。因此每个候选在被采纳之前都会被完整仿真一遍 ——
步长 0.5 ms，执行器限幅与导轨余量均已启用：

1. 用时变 LQR 沿轨迹起摆，直到捕获判据成立；
2. 随后以规划时域的四倍时间运行平衡 LQR，并包含小车设定位置的回归。
   这个时间窗必须随被控对象而变：在 `g = 1 m/s²` 时闭环比 9.81 时慢好几倍，
   固定窗口会仅仅因为“还没稳定完”就把本来可用的轨迹丢掉。

只有两步都通过的才会被采纳 —— 摆最终必须竖直且静止。这样一来，交付的轨迹
就不再依赖捕获阈值在临界情形下是否恰好准确。显示的 `eᵀPe` 即为捕获时达到的
数值。被拒绝的候选会被丢弃，搜索继续。

若起摆尝试仍然失败（轨迹走完，或撞上导轨限位），后台会启动新一轮各 20 次重启的
搜索，同时控制器再次静息 —— 最多十轮。

### 5.4 用于轨迹跟踪的时变 LQR

规划出的轨迹不是开环执行，而是被 **跟踪** 的。沿轨迹反向求解离散 Riccati 递推：

```
S_k = Q_t + AₖᵀS_{k+1}Aₖ − AₖᵀS_{k+1}Bₖ·(R_t + BₖᵀS_{k+1}Bₖ)⁻¹·BₖᵀS_{k+1}Aₖ
K_k = (R_t + BₖᵀS_{k+1}Bₖ)⁻¹·BₖᵀS_{k+1}Aₖ
```

其中 `S_N = P`（即 LQR 矩阵），`Q_t = diag(1,1,20,2,20,2)`，`R_t = 0.05`。
`Aₖ, Bₖ` 由一步 RK4 的有限差分得到。实际施加的力为

```
u = u_nom[k] − K_k·(x − x_nom[k]),   u = clamp(u, −50, 50)
```

正是这一反馈使整个方法变得鲁棒：轨迹以约 20 ms 的步长规划，而仿真以 62.5 µs
运行。实测对起始状态偏差的容忍度：±0.4 m、±0.4 m/s、±0.4 rad 与 ±0.4 rad/s
仍能被捕获（15/15 次尝试）。

---

## 6. 静息过程（RecoveryState = 1）

轨迹是从下垂静止状态出发规划的。控制器依据 2.3 节的能量平衡把系统带到那里：
`v = +k_w·W` 给出 `Ė = −k_w·W² ≤ 0`，因而无条件地抽取能量。

然而仅凭这一项会卡住。下垂的双摆有两个特征模态 —— 对默认参数，
一个在 4.22 rad/s、振型为 `[1; 1.448]`（同相），另一个在 10.94 rad/s、
振型为 `[1; −2.073]`（反相）。它们的输入耦合 `M_pxᵀ·u` 分别为 −0.4448 与
−0.0927：反相模态与小车的耦合大约要 **弱五倍**。于是在 `W ≈ 0` 的同时，
它几乎不衰减。

第二项通过对耦合 `∂(θ̈₁−θ̈₂)/∂v` 求逆，直接阻尼这一模态：

```
v = k_w·W
    − clamp( (k_rel·(θ̇₁−θ̇₂)) / (θ̈₁ᵛ − θ̈₂ᵛ), ±8 )
    − k_x·(x − x_soll) − k_d·ẋ
v = clamp(v, −12, 12)

k_w = 6.0   k_rel = 3.0   k_x = 1.5   k_d = 1.5
```

有了它，系统在所有测试过的初始状态下都能在 1–4 s 内到达静止状态，
且不会碰到导轨限位。

---

## 7. 导轨限位

导轨在 `x = ±2.5 m` 处设有硬限位。触碰时小车被置于限位处（`ẋ = 0`），
控制器切换到静息模式（状态 1）。该检测在每个积分步执行，而非每帧一次，
因此小车不可能冲过限位。

规划出的轨迹本身就会保持距离：优化中的软导轨壁垒项从 `|x| > 1.2 m` 起就开始
作用，而在所有测试过的情形中轨迹都没有超过 1.25 m。

此外，当小车正朝限位运动时，靠近限位处（±2.0 m 至 ±2.5 m）的力会被按比例衰减：

```
margin = 0.5 m
scale = max(0, (2.5 − |x|) / margin)
u *= scale  (若 ẋ 指向限位方向)
```

*注：在 “Adaptation: ON” 下，LQR 增益会在每次参数变化时重新计算。

*每次参数变化还会丢弃起摆轨迹并重新开始规划 —— 规划在后台继续进行，
与此同时控制器照常平衡或静息。*

### 已验证的工作范围

每次运行都从下垂静止状态开始；若此后摆被保持在 up-up 位姿
（`|θ| < 0.03 rad`，小车位于 `x_soll`），则记为通过：

| 参数 | 测试范围 | 结果 |
|------|----------|------|
| `M` | 0.5 – 5.0 kg | 全部通过 |
| `m₁` | 0.05 – 2.0 kg | 全部通过 |
| `m₂` | 0.05 – 3.5 kg | 全部通过 |
| `l₁` | 0.10 – 1.00 m | 全部通过 |
| `l₂` | 0.10 – 0.50 m | 全部通过 |
| `g` | 1.0 – 20.0 m/s² | 全部通过 |
| `c` | 0.00 – 0.20 Nms/rad | 全部通过 |

同样测试过：全部三个场景、四个目标角度按钮、扰动冲击
（从已平衡状态施加最大 `Δẋ = −2 m/s`、`Δθ̇₁ = Δθ̇₂ = −3 rad/s`），

**已知边界。** 在滑块的三个端点处，优化在其尝试预算内找不到能通过验收的轨迹：

* `l₂ = 1.0 m` —— 长达 2 m 的上连杆，
* `g = 35 m/s²` —— 可设定的最大重力，
* `c = 0.50 Nms/rad` —— 可设定的最大关节阻尼。

此时的行为依然温和：控制器让摆静息，在后台继续规划并重新尝试；显示区会给出
“No plan — energy pumping”。在这些设置下，**平衡** 本身 —— 场景 A 与各项扰动
测试 —— 仍然正常工作。

## 12. 实现细节

- **仿真步长：** `dt = 62.5 µs`（16 kHz），RK4
- **执行器限幅：** `|u| ≤ 50 N`，导轨 `|x| ≤ 2.5 m`
- **LQR：** 通过哈密顿矩阵的矩阵符号函数精确求解 CARE，再用 Newton/Kleinman
  精修；残差 `≈10⁻¹⁰`，耗时几毫秒
- **捕获判据：** `eᵀPe < U_max²/(K·P⁻¹·Kᵀ)` —— 不发生执行器饱和的最大子水平集
- **起摆：** iLQR，125 个节点，时域长度与下垂摆的慢特征频率挂钩，
  力通过 `tanh` 限幅
- **轨迹跟踪：** 沿轨迹用离散 Riccati 递推得到的时变 LQR，终端权重 `S_N = P`
- **后台规划：** 每动画帧 ≤ 8 ms，每帧至少执行一步优化；每次参数变化后重新规划
- **PFL：** 把期望的小车加速度精确转换为力；科氏项对关节速度是二次的
- **状态机：** 3 个状态（平衡、静息、起摆）
- **显示：** 6 个独立曲线图，150 点滑动窗口
- **语言：** 纯 JavaScript，无任何库
